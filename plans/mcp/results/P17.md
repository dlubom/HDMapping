## Praca z włączonym MCP

Ciężkie przyciski w aktualnych aplikacjach raylib uruchamiają trwałe zadania u tego samego lokalnego koordynatora, z którego korzysta MCP. Koordynator startuje na żądanie. Postęp i wynik można sprawdzać pod ID zadania. Nowa otwarta sesja o tym samym pliku ma własny identyfikator i rewizję. Auto-apply dotyczy właściwego otwarcia przy zgodnej rewizji. Po zamknięciu okna można otworzyć opublikowany wynik. Dwie operacje na odrębnych stanach mogą wykonywać się równolegle. Po zajęciu limitu kolejne zadanie czeka na wolne miejsce do rozpoczęcia przygotowania.

Przycisk anulowania i `cancel_job` nie kończą innych zadań. Żądanie może przejść przez `cancelling`. Po zatwierdzeniu publikacji koordynator zwraca wynik jako ukończony. Ponowienie po awarii używa tego samego wejścia i nowego `request_key`. Powtórzenie tego samego klucza i argumentów odczytuje istniejące zadanie.

Zwykły wynik zawiera własne zmienione pliki i może odwoływać się do niezmienionych danych źródłowych. Inwentarz rozróżnia pliki wyniku i jego zależności. Do przenoszenia projektu użyj w Step 3 pełnego eksportu `export_result` z `parameters.format=project` i bez ograniczenia zakresu. Paczka wyniku zawiera MJP, sesje MJS, pozy, chmury i trajektorie. Zasoby MCP udostępniają małe raporty, a chmury pozostają lokalnymi artefaktami.

Skonfiguruj lokalny serwer stdio z bezwzględną ścieżką do zainstalowanego adaptera `hdmapping_mcp` lub jego nazwy z prefiksem dystrybucji i rozszerzeniem `.exe` na Windows. Adapter, koordynator i worker pochodzą z tego samego pakietu. Do prób można jawnie przypisać `HDMAPPING_MCP_STATE_DIR` w środowisku serwera i badanych GUI. Każdy klient testu przeżycia musi użyć tego samego katalogu stanu.

```toml
[mcp_servers.hdmapping]
command = "/absolute/path/to/hdmapping_mcp"
```

```json
{
  "mcpServers": {
    "hdmapping": {
      "command": "/absolute/path/to/hdmapping_mcp",
      "args": []
    }
  }
}
```

Ręczny Windows 11 ma własny scenariusz. Z rozpakowanego deploy uruchomić aktualne GUI kroków 1–3.
