## Środowiska i protokół

macOS 27.0.1, build 26A434, arm64, Apple M4, 16 GB RAM; Apple clang 21.0.0 (`clang-2100.3.34.2`), CMake 4.4.3. Docker Desktop 4.72.0 / Engine 29.4.2 udostępnia Ubuntu 24.04.5 amd64 pod emulacją na LinuxKit 6.12.76. Nie jest to natywna instalacja Ubuntu Desktop. Obraz: `ubuntu@sha256:008173c23f95b170204355c12626cb5a965d779a7e1283b09e9cffbb1bf33ca3`.

Minimalny serwer: `mcp.NewServer`, `mcp.AddTool`, `mcp.StdioTransport` z oficjalnego SDK. Typ wejścia ma pole `Value int` z tagiem JSON `value`, wyjście analogiczne. Handler zwraca `Value*2`, a dla `Value<0` błąd `P00_NEGATIVE: value must be nonnegative`. Serwer loguje wyłącznie na stderr. Osobny wrapper kopiuje całe linie stdin/stdout do dwóch plików i przekazuje je bez zmian. Nie zmienia protokołu. Drugie narzędzie `p00_job` przyjmuje tylko `status` lub `advance` i łączy się z prototypem IPC.

Powtarzalne wywołanie rzeczywistego hosta (bez trwałej edycji konfiguracji użytkownika):

```sh

  --approve-for-me -C /tmp/hdmapping-p00-20261116/prototype/go \
  -c 'mcp_servers.p00.command="/usr/bin/python3"' \
  -c 'mcp_servers.p00.args=["/tmp/hdmapping-p00-20261116/prototype/wire.py"]' \
  --json 'Call p00_probe with value 7, then -1; report exact results.'
```

Pierwsza próba bez `--approve-for-me` odkryła narzędzie, ale polityka `never` zablokowała wywołania. Dopiero powyższa próba jest dowodem ich wykonania. Użyto automatycznego przeglądu zgód, bez wyłączania zabezpieczeń hosta.

## Procesy i IPC — wynik prototypu, granice wyboru

Prototyp składał się z adaptera SDK, launchera/koordynatora Go oraz C++20 workera. Launcher uruchamiał samego siebie z argumentem `daemon`, `SysProcAttr{Setsid:true}`, stdin odłączonym, stdout/stderr do pliku; `Process.Release()` zwalniał uchwyt launchera. Koordynator utrzymywał workerowi stdin/stdout niezależnie od połączenia MCP. Worker czytał `status`/`advance`, przechowywał licznik w RAM i wypisywał `{job_id,count,worker_pid}`. Stałe testowe ID `p00-job-001` nie jest implementacją tożsamości zadań produktu: ciągłość potwierdzały również niezmieniony PID i rosnący stan.

| Próba | Wynik / obserwacja |
| --- | --- |
| Codex CLI A uruchamia zadanie i kończy proces | PASS: `count=1`, `worker_pid=84362`; koordynator PID 84361. |
| Dwa uruchomienia tymczasowego okna Cocoa | PASS: oba korzystają z tego samego koordynatora; licznik osiąga 3. Pierwszy proces bez bundla nie był sterowalny przez narzędzie UI; drugi uruchomiono w tymczasowym bundlu prototypu. |
| Kliknięcie close w oknie prototypu Cocoa | PASS: okno zamknięte, aplikacja znika z inwentarza UI; koordynator i worker pozostają. Nie zamykano bieżącego czatu Codex. |
| Nowy Codex CLI B: `status`, potem `advance` | PASS: `{job_id:p00-job-001,count:3,worker_pid:84362}`, następnie count 4. |
| Ubuntu: dwa oddzielne `docker exec` uruchamiają klienta jako `p00` | PASS pomocniczy: po końcu pierwszego klienta status 1, advance 2, worker PID 17520. Nie zatrzymywano kontenera ani systemu. |
| Ubuntu, drugi użytkownik (`nobody`) łączy się z gniazdem | PASS: odmowa dostępu; katalog i socket mają 0700, właściciel `p00`. |

Wniosek do dalszej P00: **Unix domain socket + poświadczenia peera + odłączony proces użytkownika** działa w zbadanym zakresie. macOS: `LOCAL_PEERCRED`/`GetsockoptXucred`; Linux: `SO_PEERCRED`/`GetsockoptUcred`. Produkcyjny runtime musi dodatkowo sprawdzić właściciela istniejącego katalogu, odrzucać symlinki i nieaktualne endpointy, synchronizować równoczesny start oraz kontrolować wersję/tożsamość procesu zgodnie z P03. Prototyp nie udaje kompletnego supervisora, trwałego rejestru ani przeżycia restartu systemu.

Dla Windows kandydatem jest named pipe z jawną DACL bieżącego SID i odrzucaniem zdalnych klientów. Domyślna ACL nie wystarcza: [Microsoft opisuje także odczyt dla Everyone/anonymous](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights). Samo `DETACHED_PROCESS`/nowa grupa nie jest dowodem ucieczki z Job Object. [`CREATE_BREAKAWAY_FROM_JOB` wymaga zgody Job Object rodzica](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags). **Nie wybrano jeszcze zakwalifikowanej metody startu Windows; to blokada P00**, nie założenie do odłożenia na P03. Cały start w próbach odbywał się bez administratora; instalacja pakietów w jednorazowym kontenerze jest odrębną czynnością przygotowawczą.

## Odtwarzanie prób i zapis dowodów

Do odtworzenia minimalnego serwera wystarcza przykład `Getting started` z [README SDK w tagu v1.7.0](https://github.com/modelcontextprotocol/go-sdk/blob/v1.7.0/README.md) z podanym wyżej handlerem `p00_probe`. Build: `GOTOOLCHAIN=local go build`, uruchomienie `mcp.StdioTransport`, wywołanie rzeczywistym Codex zgodnie z sekcją protokołu. Nie trzeba instalować MCP produktu ani modyfikować konfiguracji użytkownika.

Próby negatywne były małe i niezależne od danych pomiarowych:

- Go format: `func badformat( ){ }`; analiza: `fmt.Printf("%d", "wrong")`; test: `t.Fatal("P00 deliberate failure")`.
- Go race: dwie goroutines czekające na wspólny kanał startowy, każda wykonuje 1000 niezabezpieczonych `x++`, WaitGroup czeka na obie. Uruchomienie `go test -race -run TestRace ./...`, potem usunięcie próbki i ponowne `go test -race ./...`.
- C++ analyzer: `int main(int argc,char**) { int* p=nullptr; if(argc>1) return *p; return 0; }`.
- C++ CTest: doctest `CHECK(7*2==14)`; chwilowa zamiana na `==15` wymaga rzeczywistej rekompilacji, potem przywrócenie i rebuild. Do końcowego macOS testu użyto `cmake --build ... --target check --clean-first`, eliminując stary obiekt.
- ASan: `volatile int index=argc; int* p=new int[1]; p[index]=42; delete[] p;` z argc=2. UBSan: `volatile int value=INT_MAX; return value+argc;`. TSan: dwie `std::thread`, `std::barrier(2)`, wspólne `volatile int value`, każda 10 000 razy `value=value+1`; join obu. Kompilacja C++20, `-g -O1 -fno-omit-frame-pointer`, odpowiednie `-fsanitize` **przy kompilacji i linkowaniu**, osobny build TSan; zdrowe uruchomienie kończy się przed sekcją błędu. Odbiór wymaga właściwego komunikatu diagnostycznego i kodu, nie dowolnego crasha.
- Procesy: launcher z `Setsid`, prywatny socket, koordynator jako jedyny właściciel stdin/stdout workera; zakończyć launchera/adapter, zamknąć okno, dopiero potem nowym klientem odczytać ID/PID/licznik i wykonać `advance`. Wynik macOS nie zastępuje scenariusza Job Object Windows.

Pliki pełnych dowodów w `evidence/`: `wire-in.jsonl`, `wire-out.jsonl`, `codex-probe-approved.jsonl`, `codex-lifetime1.jsonl`, `codex-lifetime2.jsonl`, `schema-invalid.json`, `linux-ipc-first.log`, `linux-ipc-reconnect.log`, `quality-go.json`, `sanitizer-final.json`, `mac-final-ctest.log`, `linux-*.log`, `parking-run.log`, `parking-native-read.log`, `omni-run-0011.log`, `omni-run-0012.log`, `omni-native-0011.log`, `omni-native-0012.log`, `P00Step2-gui.log`, `P00Step3-gui.log`, `vuln-verbose.log`, `xsys-update.log`, `*-xsys-*-vuln.log`, `ipc-xsys-recheck.log`, `codex-xsys-recheck.jsonl` oraz manifesty SHA256. Po próbach zamknięto okna i własne procesy prototypu oraz usunięto wyłącznie jednorazowe kontenery `hdmapping-p00-qualification` i `hdmapping-p00-final-xsys`; pliki dowodów i danych zachowano. Zakończenie pierwszego procesu okna Cocoa także nie zmieniło stanu workera (count 4, PID 84362), po czym jawnie zatrzymano koordynator. Wczesne pliki `quality-cpp-*.json` zawierają także nieudane etapy przygotowania i sam kod wyjścia; rozstrzygające są końcowe logi i opisane diagnostyki, nie automatyczna kolumna `pass` starego pomocniczego skryptu.

## Pozostałe braki kwalifikacji P00

1. **Windows 11:** rzeczywisty Codex i Claude Desktop; discovery/schema/call/error i zapis negocjacji; start bez admina, named pipe z kontrolą SID, odmowa innemu użytkownikowi; koordynator i C++ worker po zamknięciu obu klientów i okna; szczególnie Job Objects. Testy Go/C++, MSVC `/W4 /WX`, wersje narzędzi i źródła/checksums.
2. **Claude Desktop:** uwierzytelniony klient na dostępnych oficjalnie wspieranych platformach, także macOS; nie zastępować SDK. Uwzględnić aktualne wsparcie Linux beta.
3. **Ubuntu 24.04:** rzeczywisty host AI i GUI oraz niezależność procesów po zamknięciu. Działający Linux TSan z dodatnią i ujemną próbką; obecny kontener odmawia `personality`. Uzupełnić brakujące platformowe próby formatu/analizatorów i uzgodnić finalną macierz tych samych wersji lokalnie/CI. Kontener daje tylko wskazane dowody pomocnicze.
4. **Dane:** potwierdzić nakładanie wybranego zestawu na chmurach, w razie potrzeby zmienić podzbiór; przygotować bazową rejestrację/optymalizację kroku 3, kompletny `.mjp` i natywny odczyt po zamknięciu procesu. Powtórzyć wykonaną optymalizację GUI kroku 2 Parking i dokończyć jej zapis oraz natywny odczyt; same logi NDT nie zastępują utrwalonych poses. Nie uznawać GNSS 58,6 m ani dwóch niezależnych odometrii za ukończony fixture wielosesyjny.
5. Domknąć macierz końcowego zestawu z x/sys v0.44.0: przyszły Windows IPC i wszystkie rzeczywiście użyte build tags. Dostępne powtórzenia macOS/Codex/Linux oraz skany serwera są zaliczone powyżej. Po powrocie do kwalifikacji domknąć wybór IPC/startu Windows i wersji; przeprowadzić przegląd raportu, kontrole dokumentacji, commit `[skip ci]`, zwykły push `mcp/p00` tylko do forka, sprawdzić zdalny SHA i odczyt raportu.
